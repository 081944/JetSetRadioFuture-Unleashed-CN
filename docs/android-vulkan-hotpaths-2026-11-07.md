# Vulkan 管线与共用前端优化（2026-11-07）

按用户要求保持 AYN Thor 的 CPU 锁频，不调整性能模式、调频策略或温控。
基于当前 `cn` 工作区，保留此前已验证的宽屏和手柄修复。

## 改动

- 管线缓存从遍历全部条目改为 4096 个哈希桶和索引链，仍比较完整的原始
  key。最多 8192 条记录，程序释放后的无效句柄被跳过，程序 ID 重用不返回
  旧管线，退出时清空索引。没有改动管线状态、GPU 同步和资源退休规则。
- 纹理抽样哈希将四个多项式项合并计算，采样地址、字节数、颜色格式、bias
  和输出保持不变；诊断用的全内容模式也保留。每次 lookup 的源数据抽样、
  每帧完整内容校验预算和顶点内容哈希均未减少。
- 共用前端的高频入口内联读取已缓存的启用状态，公共 API 保持原有语义。
  编译产物确认没有对公共 `nv2a_gl_enabled` 的 CALL/JUMP 重定位。
- 重复上传相同顶点微码时不增加内容 generation，避免无效地丢弃解码与哈希
  memo。实际有变化的每个 word 仍使缓存失效；上传游标、部分指令和完成标志
  的推进逻辑保持原样。

## 验证

`python tools/cn_compat/test_renderer_hotpaths.py` 提取实际函数做差分验证。
覆盖全部 8192 条管线、哈希碰撞、程序释放和 ID 重用、key 中每个字节的变化、
索引复位、纹理边界尺寸与未对齐数据、采样/全内容模式、原地修改和 bias、
启用状态缓存、微码重复写入与变更失效。主机和 AYN Thor 的 ARM64 可执行测试
均通过。手柄脚本、Vulkan uniform 回归也通过。

NDK 29、`-O2 -g1`、两路并行的完整原生库编译链接通过，`git diff --check` 通过。

## 设备独立微基准

每组 400,000 次，三次结果取中位数。测试直接运行在当前 AYN Thor 上，
不切换性能模式；游戏仍在运行，因此存在调度扰动。管线 key 使用随机状态，
数量与采样时的 285 条相同；不等同于游戏的实际 key 分布。

| 路径 | 原实现 | 新实现 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 285 条管线缓存查找 | 104.954 ms | 24.659 ms | 76.5% |
| 纹理抽样哈希 | 20.992 ms | 16.050 ms | 23.5% |

这些数据只说明被测试函数变快，不能换算成整场景 FPS 提升。
前一轮现场采样中的状态派发、纹理/顶点校验和游戏逻辑仍有其他成本。

原始资料：`build/logs/20261107-hotpaths/`，包括测试 C、设备可执行文件、三次
日志、全内容模式测试、编译日志与 `summary.json`。
