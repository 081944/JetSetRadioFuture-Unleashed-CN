# Android 副屏常驻地图

主屏继续使用现有 Vulkan 游戏渲染。Android `Presentation` 在可用的第二块屏幕上显示独立地图，默认开启；游戏设置中的“副屏地图”可以关闭。下屏单指拖动旋转，双指缩放，双击恢复该地图的原版默认方向。

## 数据与渲染

- 地图和文字、标记使用用户游戏目录内原版 `Media/Disp/map/StageNN.dat`、`Media/Disp/SprNorm.dat` 的模型，不复制或分发游戏资源。
- `MapAsset.java` 解析 MULT/NORM 容器、MDLB 模型、带材质的三角形/条带及顶点法线，并将解析结果缓存在下屏 GLES 上下文的静态顶点缓冲中。右侧暂停菜单不参与绘制。
- 材质 diffuse 是原版 `sub_00186A30` 解码的 ARGB，必须保留最高字节的透明度。涩谷模型的根节点面 alpha=0，灰色外壳 alpha=63/255；旧测试实现错误地把二者都设成 1，造成实体“盖子”和灰色偏色。完全透明面跳过，半透明外壳在不透明面后混合、不写深度。
- `map_snapshot.c` 仅在副屏启用时由游戏主循环读取地图数据，约 30 Hz 发布一份有界快照。Java 经互斥锁复制快照，从不跨线程读取或修改 guest RAM。
- 同步场景编号、玩家位置/朝向、地图出口和地点名、尚未完成的涂鸦点、拾取物；加载交接时清除旧场景。默认旋转来自原版地图参数表。CN 与 US 全局地址分别选择。
- 下屏窗口不取得焦点；地图区域触摸调整副屏本地视图，底部角色按钮通过独立请求交给游戏线程处理。拔掉/关闭副屏、后台运行或关闭设置时，停止请求地图帧及发布快照。
- 地图摄像机沿用原版左手坐标及 Z/Y/X 旋转顺序，进入 GLES 时明确反射相机 Z，并相应转换正面绕序。不能直接用从 +Z 观察的普通 `lookAt`，否则地图前后方向会颠倒。仅改变剔除绕序也不能解决强制不透明材质导致的盖子。
- 按当前模型视图矩阵转换法线，使用原版地图的正面白色方向光；不添加额外的环境底色或暖色高光。3D 标记保留深度测试及面剔除，避免背面的深红描边覆盖橙色正面；地点名面向下屏。

## 验证

- `tools/cn_compat/MapAssetTest.java`：从本地游戏资源读取 27 个地图模型、28 个有效标记模型（资源表内存在空槽），校验索引、材质、顶点范围和错误文件拒绝。增加涩谷模型透明度回归：1128 个不透明顶点和 1128 个 alpha=63/255 的外壳顶点，alpha=0 的根节点不进入绘制。
- `tools/cn_compat/test_map_snapshot.c`：Android 原生可执行测试，在开发用 RAM 快照中验证当前场景、玩家位置及 55 个标记，检查禁用、缓冲长度、场景加载交接、非法根指针。
- Android Java 与 NDK 原生编译通过。AYN Thor 已验证 display 4 的独立窗口与触摸拖动，主屏继续运行。用户指出首轮包的镜像、封闭外壳和颜色问题；28 版修正透明度、绕序、标记深度与法线照明。

## 构建测试示例

在 PowerShell 7 中运行，测试编译产物使用忽略的目录。需要本地已提取的游戏文件；不附带测试数据。

```powershell
$ErrorActionPreference = 'Stop'
New-Item -ItemType Directory -Force build/logs/secondary-map/classes | Out-Null
& "$env:JAVA_HOME/bin/javac.exe" -encoding UTF-8 -d build/logs/secondary-map/classes launcher/android/java/com/jumatt/jsrfunleashed/MapAsset.java launcher/android/java/com/jumatt/jsrfunleashed/MapPlaceNames.java tools/cn_compat/MapAssetTest.java
if ($LASTEXITCODE -ne 0) { throw 'javac failed' }
& "$env:JAVA_HOME/bin/java.exe" -cp build/logs/secondary-map/classes com.jumatt.jsrfunleashed.MapAssetTest game_files/cn-extraction-test
if ($LASTEXITCODE -ne 0) { throw 'map asset test failed' }
```

30/31 版将触摸增量应用于摄像机坐标，避免道玄坂等地图的默认滚转交换上下/左右手势轴；保留 29 版的水平反向操作。
